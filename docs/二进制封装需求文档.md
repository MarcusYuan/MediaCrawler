# MediaCrawler 二进制 CLI 封装需求文档

> 版本：v0.1（需求阶段，未开始实施）
> 目标：将 MediaCrawler 封装为自包含的单文件可执行程序，用户免安装即可使用。

## 1. 背景与问题

当前使用 MediaCrawler 的前置步骤过多：

1. 安装 Python ≥ 3.11
2. 安装 30+ 个 pip 依赖（含 opencv、pandas、playwright 等重型库）
3. `playwright install` 下载浏览器
4. 使用抖音/知乎平台还需要系统安装 Node.js（`pyexecjs` 签名依赖）
5. 通过 `python main.py ...` 运行

对非开发背景的用户门槛过高。

## 2. 目标用户体验

```
下载单个可执行文件
  → (macOS/Linux) chmod +x mediacrawler
  → mediacrawler --platform xhs --lt qrcode --type search
  → 首次运行自动初始化配置与数据目录（~/.mediacrawler/）
```

- 用户机器上**唯一的前提**是装有 Chrome/Edge（绝大多数人已满足）
- 无需 Python、无需 pip、无需 playwright install、无需 Node.js
- 现有 Typer CLI 的全部参数与 `--help` 原样保留

## 3. 已确认的事实（依赖审计结论）

以下结论来自对当前代码的逐项核查，是本需求的技术基础：

| 依赖 | 用途 | 必需性 | 封装策略（已定） |
|------|------|--------|------------------|
| Chrome/Edge | CDP 模式驱动本机浏览器（默认 `ENABLE_CDP_MODE=True`） | 必需（全平台） | 不打包，用用户本机浏览器 |
| Node.js | `pyexecjs` 编译执行 `libs/douyin.js`、`libs/zhihu.js` 生成请求签名 | 抖音/知乎必需 | 内嵌：复用 playwright pip 包自带的 node（实测 116.5MB，`playwright/driver/node`） |
| ffmpeg | B站 DASH 视频/音频合流 | 可选 | 不打包；代码已有优雅降级（缺失时存单流直链） |
| 其余全部依赖 | — | — | 均为 pip wheel 产物，可被冻结进二进制 |

补充事实：

- 仓库内**无任何** `.so`/`.dylib`/`.dll`/字体等原生文件
- MySQL/PostgreSQL/MongoDB/Redis 均为可选外部服务，默认存储 jsonl/csv/sqlite 不依赖它们
- WebUI（`webui/` + `api/`）是独立形态，CLI 模式不需要，**不纳入封装范围**

## 4. 代码层面必须解决的问题（封装前置改动）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| P1 | 相对路径资源加载 | `media_platform/douyin/help.py:37`、`media_platform/zhihu/help.py:50`、各平台 `core.py` 的 `add_init_script(path="libs/stealth.min.js")` | 全部假设 CWD=仓库根；需改为从打包资源路径（`sys._MEIPASS` 或模块路径）解析 |
| P2 | execjs 运行时绑定 | `media_platform/douyin/help.py`、`media_platform/zhihu/help.py` | 默认从系统 PATH 找 node；需改为优先使用内嵌 node |
| P3 | 配置为 Python 源码 | `config/*.py` | 打包后不可修改；需支持首次运行在 `~/.mediacrawler/` 生成外部配置（格式待定） |
| P4 | 数据输出路径 | 默认相对路径 `data/` | 打包形态下应默认落到 `~/.mediacrawler/data/` 或显式 `--save_data_path` |

## 5. 功能需求

- **FR1** CLI 行为与现有 `python main.py` 完全一致（全部参数、枚举、默认值逻辑）
- **FR2** `libs/*.js`（stealth.min.js、douyin.js、zhihu.js）内嵌并正确加载
- **FR3** 抖音/知乎签名在**无系统 Node** 的机器上正常工作（使用内嵌 node）
- **FR4** 首次运行自动生成用户目录：`~/.mediacrawler/`（配置 + 数据 + 日志）
- **FR5** 目标平台：macOS arm64、macOS x64、Linux x64、Windows x64（各出一个单文件）
- **FR6** `--version` 显示版本；`--license`（或 about）展示上游版权与许可证（授权条款要求）
- **FR7** 构建流程可自动化（CI 矩阵构建四个平台产物）

## 6. 非功能需求

- **NFR1** 单文件体积（压缩后）目标 ≤ 400MB
- **NFR2** 冷启动（含 onefile 解压）目标 ≤ 15 秒
- **NFR3** 运行不需要管理员/root 权限
- **NFR4** 除正常爬取流量外，运行时不联网下载任何组件（"开箱即用"承诺）
- **NFR5** 不修改上游代码的行为语义——所有改动为"资源路径解析"与"配置来源"层面的适配，便于后续与上游同步

## 7. 约束

1. **上游许可证**：非商业学习许可 1.1。允许自用/修改/复制；分发副本须保留版权与许可声明；不得商用（详见 `LICENSE`）
2. **无交叉编译**：主流 Python 冻结方案均需在目标系统上原生构建 → 必须用 CI 矩阵
3. **macOS Gatekeeper**：未签名二进制会被拦（用户需 `xattr -c` 绕过，或投入 Apple 开发者账号做签名+公证）——是否投入待定
4. **Playwright 禁止改名/改结构**：driver 目录结构（含 node）是包的组成部分，打包时需完整收集

## 8. 本期范围外

- ❌ 不内嵌浏览器（CDP 用本机 Chrome）
- ❌ 不内嵌 ffmpeg（已有降级逻辑；未来可提供 `full` 变体）
- ❌ 不打包 WebUI / FastAPI 后端
- ❌ 不做 GUI
- ❌ 不做代码混淆/加密

## 10. 验收标准

在**干净环境**（仅有 Chrome，无 Python/Node/pip）中：

1. [ ] macOS：下载单文件 → 运行 `--help` 正常
2. [ ] 小红书：扫码登录 → 关键词搜索爬取 → jsonl 输出到 `~/.mediacrawler/data/`
3. [ ] 抖音：在无系统 Node 的机器上完成签名并爬取成功
4. [ ] 修改 `~/.mediacrawler/` 下的配置后重新运行，配置生效
5. [ ] `--version` / 许可证信息可见
6. [ ] 体积与冷启动满足 NFR1/NFR2
