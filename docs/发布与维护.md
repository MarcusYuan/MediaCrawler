# 发布与维护指南（维护者文档）

> 面向本项目维护者。用户文档见 `README.md`。

## CI/CD 触发规则

| 触发条件 | Workflow | 行为 |
|---|---|---|
| push 到 `main` / 提交 PR | `ci.yml` | 全量测试 + 构建命令校验（不出产物） |
| 推送 `v*` 标签（如 `v0.2.0`） | `release.yml` | 四平台矩阵构建（macOS arm64/x64、Linux x64、Windows x64）→ 冒烟测试 → sha256 校验和 → 自动创建 GitHub Release |
| Actions 页面手动触发 | `release.yml` (dispatch) | 只构建不出 Release，用于测试流水线 |
| push 到 `main`（上游的 `deploy.yml`） | 文档站部署 | 已加仓库守卫，本 fork 自动跳过 |

## 发版流程

```bash
# 1. 版本号单一事实源：tools/box_contract.py 的 APP_VERSION（裸 semver）
#    修改后提交并合入 main（CI 会先跑全量测试）
# 2. 从 main 打标签并推送：
git tag v<版本号> && git push origin v<版本号>
# 3. 等待约 2 小时（Windows 构建最慢），Release 页自动出现四平台产物 + sha256
```

注意：标签必须打在包含 `release.yml` 的提交上（合并到 main 后的 main 提交天然满足）。

## 构建产物说明

| 产物 | 体积（v0.1.1 实测） | 说明 |
|---|---|---|
| macos-arm64 / macos-x64 | ~162MB / ~161MB | 未签名，用户需 `xattr -c`；部署目标当前跟随构建机 SDK（待降基线） |
| linux-x64 | ~231MB | ubuntu-22.04 基线（较老 glibc）；必须安装 `zstandard` 否则不压缩（866MB 教训） |
| windows-x64.exe | ~162MB | MinGW64 构建（CI 自动下载）；杀软误报待观察 |

## 本地构建

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt nuitka
brew install ccache                        # macOS，可选但强烈建议
.venv/bin/python scripts/build.py          # 跨平台；--dry-run 预览命令
./scripts/build-macos-arm64.sh             # 等价本地薄包装
```
