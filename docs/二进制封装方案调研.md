# 二进制封装方案调研

> 版本：v0.1（2026-09 调研，未开始实施）
> 配套文档：《二进制封装需求文档》

## 1. 调研问题

针对"Python + Playwright(CDP 模式) + 内嵌 Node + 30 余个重型依赖 → 跨平台单文件可执行"这一场景，选择哪个封装工具。

## 2. 候选方案全景（快速淘汰）

| 方案 | 原理 | 单文件 | 结论 |
|------|------|--------|------|
| **PyInstaller** | 打包器：字节码 + 解释器冻结 | ✅ onefile | **进入决赛** |
| **Nuitka** | 编译器：Python → C → 机器码 | ✅ onefile（解压缓存） | **进入决赛** |
| cx_Freeze | 打包器 | ❌ 只出目录 | 淘汰：无真单文件 |
| Briefcase (BeeWare) | 原生 App 打包 + 平台安装器 | ❌ 目录型 App | 淘汰：面向 GUI 原生应用，CLI 单文件场景不适配 |
| PyOxidizer | Rust 嵌入式解释器 | ✅ | 淘汰：2024-03 起作者明确弃维护（indygreg/PyOxidizer#3081） |
| PyOxy / python-build-standalone | 便携 Python 发行版 | — | 淘汰：不是打包器，解决不了依赖收集 |
| Docker | 容器镜像 | — | 淘汰（需求阶段已排除）：对小白用户反而更复杂 |

## 3. 决赛对比（针对本项目场景）

### 3.1 Playwright 支持度

| 维度 | PyInstaller | Nuitka |
|------|-------------|--------|
| 官方/生态支持 | **Playwright 官方文档有专门的 PyInstaller 章节**，`--collect-all playwright` 即可收齐 driver（含 node 二进制） | Nuitka 内置标准插件 `--enable-plugin=playwright`，自动处理 driver 文件 |
| 我们的简化点 | 官方教程的核心难点是"内嵌浏览器"（`PLAYWRIGHT_BROWSERS_PATH`）；**我们走 CDP 模式用本机 Chrome，不需要浏览器**，只需 driver/node，场景比官方教程更简单 | 同左 |

**结论：平手**。两者都有成熟路径，且我们的 CDP 决策砍掉了最难的部分。

### 3.2 onefile 解压行为（对我们 500MB 级负载最关键的差异）

| 维度 | PyInstaller | Nuitka |
|------|-------------|--------|
| 解压策略 | **每次运行都解压到临时目录，退出删除，无缓存** | **首次运行解压到缓存目录（`--onefile-tempdir-spec` 可配），后续运行直接复用**（按应用/版本校验） |
| 对我们的影响 | 每次运行多付 5~15 秒 + 临时盘占用 | 只有第一次慢，之后启动正常 |

**结论：Nuitka 明显占优**。对 CLI 工具（反复运行）这是用户体验的决定性差异。

### 3.3 依赖兼容性（30+ 重型库：opencv/pandas/matplotlib/sqlalchemy/cryptography/fastapi…）

| 维度 | PyInstaller | Nuitka |
|------|-------------|--------|
| 机制 | 不编译，只收集 → 兼容性风险最低 | 真编译成 C，边角问题概率更高 |
| 现状 | 多年事实标准，重库支持成熟 | 2.x 已大幅成熟（anti-bloat、各库 yaml 配置），但历史上有科学计算栈踩坑记录（pandas #557 等已修复）；opencv/matplotlib 需显式 data-files 配置 |

**结论：PyInstaller 占优**（稳妥）。

### 3.4 Windows 杀软误报

- PyInstaller onefile 是**重灾区**：bootloader 特征被大量恶意软件共用，VirusTotal 常见 4+ 误报；官方 issue 长期开放
- Nuitka：真 C 编译、无 Python bootloader，误报显著更少，但**并非免疫**
- 两者的共同解法：代码签名证书（最有效）、onedir 形态、向 Defender 提交白名单

### 3.5 其他维度

| 维度 | PyInstaller | Nuitka |
|------|-------------|--------|
| 运行性能 | 与 CPython 持平 | 快 2~4 倍（对 IO 型爬虫**无意义**） |
| 产物体积 | 较小 | 较大（编译产物 + 静态链接） |
| 构建耗时 | 分钟级 | 可能 30min~2h+（CI 可用 ccache 缓解） |
| 构建环境 | 无需编译器 | 需 C 编译器（CI 镜像可满足） |
| macOS 签名 | 需处理 Gatekeeper（同左） | 需处理 Gatekeeper |

## 4. 推荐结论：双轨验证，终选倾向 Nuitka

> **更新（2026-09-19）：已选定 Nuitka，PyInstaller 降级为兜底备选。**
> 专项落地研究见《Nuitka 封装专项研究》。
> ⚠️ 同时修正一处：Nuitka onefile 的"解压缓存"**并非默认行为**——默认规格 `{TEMP}/onefile_{PID}_{TIME}` 每次运行解压后删除；必须显式设置 `--onefile-tempdir-spec` 为静态路径（如 `{CACHE_DIR}/{PRODUCT}/{VERSION}`）才能获得缓存复用。本文 3.2 节的对比结论在**正确配置后**依然成立。

**推荐策略**：需求文档中的 P1~P4 前置代码改动（资源路径、execjs 绑定内嵌 node、配置外置、数据目录）**与封装工具无关**，先做完这些；然后两条轨道各出一个原型，用实测数据定终选：

```
量测指标（每平台）：
  ① 单文件体积（压缩后）
  ② 首次冷启动耗时（含解压）
  ③ 二次启动耗时
  ④ xhs/dy 完整爬取冒烟测试（重点：无系统 Node 时 dy 签名）
  ⑤ Windows Defender / VirusTotal 误报数
```

**当前倾向**：**Nuitka onefile + `--enable-plugin=playwright`** 作为最终分发形态，理由排序：

1. 解压缓存机制在大体积场景下是用户体验的分水岭（PyInstaller 每次运行 5~15 秒惩罚，对一个 CLI 工具是硬伤）
2. Windows 误报更少（若分发范围含 Windows 用户）
3. 依赖兼容性风险通过"PyInstaller 平行轨道"兜底——若 Nuitka 在我们的依赖栈上翻车且短期内无解，PyInstaller 是随时可切换的退路

## 5. 风险清单（两轨共通）

| # | 风险 | 缓解 |
|---|------|------|
| R1 | macOS Gatekeeper 拦截未签名二进制 | 初期文档说明 `xattr -c`；后期可投 Apple 开发者签名+公证 |
| R2 | Windows 杀软误报 | 签名 / onedir 变体 / 提交白名单 |
| R3 | execjs 找不到内嵌 node | 前置改动 P2 明确绑定；冒烟测试覆盖"无系统 Node"环境 |
| R4 | 上游同步冲突（P1~P4 改动触碰的文件上游也在改） | 改动集中、风格跟随上游；`douyin/help.py` 等文件历史上活跃，同步时重点review |
| R5 | Nuitka 编译期不兼容个别依赖 | PyInstaller 兜底轨道 |
